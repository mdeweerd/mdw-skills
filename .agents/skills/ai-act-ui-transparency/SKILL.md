# Apply EU AI Act transparency and prohibited-practice rules to a conversational AI UI

Non-negotiable design requirements from [Regulation (EU) 2024/1689 (AI Act)](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) for any conversational AI user interface (text chat, voice assistant, interactive kiosk, online demo), regardless of who operates it as provider or deployer. This skill is generic: the project-specific decisions (exact wording per language, exact placements, persistence behaviour) must be recorded in the target project, for example in a project-specific companion skill, and updated in the same change that alters them.

## When to Use

- Any change to the UI (pages, components, layout) of an AI-driven interface
- Any change to the conversation flow (written or voice input, answer rendering)
- Adding or removing a supported language
- Adding voice output (TTS), emotion recognition, or AI-generated content (image, audio, video)
- AI Act compliance review before a release

## Regulatory context

| Obligation | Content | Applicable since |
|---|---|---|
| [Art. 5](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32024R1689#art_5), prohibited practices | Manipulative or subliminal techniques, exploitation of vulnerabilities, dark patterns, emotion recognition (in the cases provided for) | 02/02/2025 |
| [Art. 50(1)](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32024R1689#art_50), interaction transparency | Clearly, and at the appropriate time, inform the user that they interact with an AI system (unless obvious from the context) | 02/08/2026 |
| [Art. 50(2)-(4)](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32024R1689#art_50), generated content | Visible labelling of deep fakes; machine-readable marking by the provider of the generative system | Depending on the paragraphs |

## Rule 1: Interaction transparency (Art. 50(1))

Every person who enters a dialogue with the AI must be informed, clearly and at the appropriate time, that they interact with an artificial intelligence, in every language the interface supports.

### Required disclosure placements

| # | Placement | When | Wording pattern |
|---|---|---|---|
| 1 | Dialogue entry screen, inside the input area | At dialogue start, clearly visible | "You are interacting with an artificial intelligence (AI)." |
| 2 | First displayed AI answer of the session | With the first rendered answer | "This answer is generated by an artificial intelligence." |
| 3 | First spoken answer of the voice flow (only if a TTS output exists) | With the first spoken answer | "This answer is generated by an artificial intelligence." |
| 4 | Discreet persistent notice | During the whole AI dialogue | "AI. Answers are generated by an artificial intelligence." |

- A legal or "about" page must never carry the only disclosure. Art. 50(1) requires an appropriate moment, at or before the first interaction. Such a page may complete the disclosure but never replaces it.
- The persistent notice applies only to screens that display AI-generated dialogue content. Screens that display business data that the AI did not generate carry no persistent notice.

### Forbidden formulations

- Any wording that suggests a human interlocutor. An assistant avatar must be labelled as an AI assistant, for example an aria-label such as "AI assistant" plus a visible "AI" badge. A human job title as the avatar label is forbidden.
- Any disclosure buried in the terms of use or a legal page, with no on-screen display at the moment of the interaction.

### Multilingual handling

- Single source of truth: one i18n data module holds every AI-disclosure string, with one object per supported language containing all keys: entry, first answer, voice, persistent notice, avatar.
- The active UI language must also drive the locale of the speech input (for example SpeechRecognition) when voice input exists.
- Absolute rule: every added language must define all keys with non-empty values. A validation check must fail the build otherwise.
- Never hard code a disclosure string in a component. Always resolve it through the i18n module.

## Rule 2: Prohibited practices (Art. 5)

- No manipulative or subliminal technique in the UI or in the user journeys.
- No exploitation of vulnerabilities (health context, elderly people, and any other vulnerable group): no pressure, no guilt, no artificial urgency in the copy.
- No dark pattern: declining (not starting the demo, quitting, ignoring) must be as simple as accepting. No aggressive purchase pressure.
- No emotion recognition, no sentiment analysis, no inference about the emotional state of the user. Art. 5(1)(f) prohibits emotion recognition in workplace and education contexts; outside those contexts the system is at least high-risk (Annex III, point 1(c)) and triggers the Art. 50(3) duty to inform the persons exposed. This skill excludes the feature from the UI in all cases: do not add it. Guard: a case-insensitive scan of the source with the generic pattern below must return nothing.

```sh
git grep -nEi 'emotion[-_ ]?(recognition|detection|classification|analysis|infer)|sentiment[-_ ]?(analysis|score|classification)|facial[-_ ]?(expression|recognition|analysis|landmark)|face[-_ ]?(api|recognition|detection|tracking|mesh|landmark)|micro[-_ ]?expression|affectiva|affective|deepface|openface|gazepoint|eye[-_ ]?track|gaze[-_ ]?(track|estimat|detect)|webgazer|tracking\.js' -- src
```

- Adapt the path (`src`) to the source root of the target project. Review every hit: a translated UI string that only mentions a listed word is a false positive, but any API call, package import, model invocation, or personal-data collection behind it is a violation.
- Extend the pattern with the emotion-analysis, face-analysis and gaze-tracking SDK, package and model names present in the target project, and check the dependency manifest for those names as well. Record the extended pattern in the project decisions.

## Rule 3: AI-generated content (Art. 50(2)-(4))

- If the UI displays AI-generated images, audio or video, the visible labelling requirement applies only to deep fakes (real persons, places or events) and to texts published to inform the public on matters of public interest.
- Machine-readable marking is the duty of the provider of the generative system (the AI service), not of the UI. Keep any existing "Generated by AI" note next to the AI-generated content the UI displays.

## Record the project decisions

Keep a per-project record of the disclosure implementation, mapping each placement to the screen or component, the exact wording per language, the persistence behaviour, and the project-specific extension of the emotion-recognition scan pattern. Update this record in the same pull request as any change to these decisions.

## Validation

- [ ] The disclosure i18n check passes: every supported language has all keys, non-empty
- [ ] Every disclosure string resolves through the i18n module; a search for a hard-coded disclosure sentence in the components returns nothing
- [ ] No human-interlocutor label remains: no human job title labels the assistant avatar
- [ ] No emotion-recognition or user-inference feature in the source: the generic scan pattern plus the project-specific SDK, package and model names returns nothing, every hit is reviewed, and the dependency manifest contains none of those names
- [ ] The disclosure does not exist only on a legal page: the dialogue entry screen and the first answer display it through the i18n module
- [ ] The persistent notice renders only on the AI-dialogue screens
- [ ] Every new language added to the interface appears in the i18n data module with all keys translated

## Common Pitfalls

- Disclosure only on an "about" page: not compliant. Art. 50(1) requires an appropriate moment, and a legal page is not one.
- Assistant avatar with a human label or a human aria-label: forbidden formulation, even if a disclosure exists elsewhere.
- Hard-coded disclosure string in one language inside a component: blocks multilingual support. Use the i18n module.
- Language added without its translations: the i18n check must break the build, otherwise the check is missing.
- Confusing Art. 50(1) and Art. 50(2)-(4): transparency of the interaction (who the user talks to) is not the labelling of generated content.
- Persistent notice on every page: screens with non-AI business data carry no obligation, and the notice clutters the UI without a legal requirement. Limit it to the AI-dialogue screens.
- Scan limited to the baseline pattern: any emotion-analysis or face/gaze-tracking SDK, package, service or model name added to the project extends the pattern in the same change. A clean baseline scan alone is not evidence of compliance.
- Weakening the pattern after false positives: review hits case by case. A translated string that only mentions a listed word is a false positive; an API call or a personal-data collection behind it is a violation. Remove the finding, not the check.
